# AI 小说转剧本工具 — 项目计划

## 一、项目概述

### 1.1 项目背景
传统的小说改编为剧本（影视剧本/漫画剧本）需要编剧投入大量时间和精力进行手工改写。借助大语言模型（LLM）的能力，可以实现从小说文本到剧本格式的智能转换，大幅提升改编效率。

### 1.2 项目目标
构建一个基于 AI 的小说转剧本平台，支持用户上传小说文本，自动完成：
- 小说章节解析与结构化
- 角色识别与关系梳理
- 场景拆分与对白提取
- 剧本格式化输出（支持多种剧本格式）

### 1.3 目标用户
- 影视/动漫编剧
- 漫画工作室
- 网文创作者
- 内容改编从业者

## 二、核心功能

### 2.1 MVP（最小可行产品）

| 模块 | 功能 | 说明 |
|------|------|------|
| **文本输入** | 小说上传/粘贴 | 支持 TXT/EPUB 文件上传，或直接粘贴文本 |
| **章节解析** | 自动分章 | 识别章节标题，将长文本拆分为章节 |
| **剧本改编** | AI 驱动改写 | 将小说叙述体转换为剧本格式（场景+对白+舞台指示） |
| **剧本输出** | 导出 | 支持导出为标准剧本格式（Markdown / PDF / Word） |

### 2.2 后续迭代功能

| 模块 | 功能 | 说明 |
|------|------|------|
| **角色管理** | 角色自动提取 | AI 识别小说中的角色名、性格、关系 |
| **风格定制** | 改编风格选择 | 影视剧本 / 漫画分镜剧本 / 舞台剧剧本等多种风格 |
| **批量处理** | 多章节批处理 | 一次性处理整部小说，逐章输出剧本 |
| **人工校对** | 在线编辑器 | 提供剧本编辑器，支持人工修改和校对 |
| **版本管理** | 历史版本 | 保存改编历史，支持版本回溯 |
| **API 服务** | 开放 API | 提供 REST API，支持第三方集成 |

## 三、技术架构

### 3.1 整体架构

```
┌─────────────────────────────────────────────┐
│                  前端 (Web UI)                │
│         React + TypeScript + Tailwind        │
├─────────────────────────────────────────────┤
│                  后端 API                     │
│          Python FastAPI / Node.js             │
├─────────────────────────────────────────────┤
│              AI 引擎层 (LLM)                   │
│     Claude API / GPT API / 开源模型           │
├─────────────────────────────────────────────┤
│                 数据存储层                     │
│      PostgreSQL + Redis + 对象存储            │
└─────────────────────────────────────────────┘
```

### 3.2 推荐技术栈

| 层级 | 技术选择 | 说明 |
|------|----------|------|
| **前端** | React + TypeScript + TailwindCSS | 现代化 UI，响应式设计 |
| **后端** | Python FastAPI | 异步支持好，AI 生态丰富 |
| **AI 引擎** | Claude API (主力) + 通义千问 (备选) | 长文本处理能力强 |
| **数据库** | PostgreSQL + pgvector | 支持文本向量检索 |
| **缓存** | Redis | 任务队列 + 结果缓存 |
| **文件存储** | MinIO / 阿里云 OSS | 存储上传的小说和输出的剧本 |
| **部署** | Docker + Nginx | 容器化部署 |

### 3.3 AI 处理流水线

```
小说输入 → 文本预处理 → 章节切分 → 角色提取
                                    ↓
          剧本输出 ← 格式整理 ← AI 逐章改编
```

**关键 AI Prompt 设计方向：**
1. **系统提示词**：定义剧本改编的规则（格式规范、改写原则）
2. **章节分析**：识别场景、角色、对白、叙述
3. **改编生成**：将叙述转换为剧本对白+舞台指示
4. **质量控制**：检查剧本连贯性、角色一致性

## 六、Prompt 工程设计要点

### 6.1 系统级 Prompt 模板

```
你是一位资深的影视编剧，擅长将小说改编为剧本。

改编规则：
1. 保留原著的核心情节和人物对话
2. 将叙述性文字转换为「舞台指示」（用【】标注）
3. 对白保留原汁原味，必要时可适当精炼
4. 每个场景需要标注：场景序号、地点、时间、出场人物
5. 输出格式为：

第X场
时间：XX 地点：XX 人物：XX
【舞台指示描述】
角色A：（对白内容）
角色B：（对白内容）
```

### 6.2 分步处理策略

对于长章节，采用分步处理：
1. **第一步**：提取场景列表
2. **第二步**：逐场景生成剧本
3. **第三步**：拼接并检查连贯性

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| AI 生成质量不稳定 | 剧本质量差 | 多轮改写 + 人工校对流程 |
| 长文本超 Token 限制 | 无法一次处理 | 章节切分 + 分段处理 |
| 角色名不一致 | 剧本混乱 | 先提取角色表，改编时参考 |
| API 成本过高 | 运营成本压力 | 缓存 + 本地小模型做预处理 |
| 版权问题 | 法律风险 | 仅限用户自有版权内容 |
